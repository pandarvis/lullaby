# Lullaby V1 — Git Inspector Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for the recommended sequential execution, or superpowers:subagent-driven-development if the user selects delegation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consulter le graphe commits/branches/merges et l'arborescence des fichiers
modifiés, avec diffs, dans le projet ouvert de Lullaby.

**Architecture:** Le main interroge Git local et retourne des relevés typés par
projet. React affiche le graphe SVG, l'arbre des changements et les différences.
La vue est indépendante des moteurs d'agents et réutilise le pont limité de la V0.

**Tech Stack:** Git installé, Node child_process, React/TypeScript, SVG et styles
Iris ; Vitest déjà introduit dans la V0. Aucun serveur ou module Git natif ajouté.

**Spec:** [Vue Git V1](../specs/2026-09-26-v1-git-design.md).

Statut : plan proposé ; exécution après le [socle V0](2026-09-26-v0-windows.md).
Tous les fichiers et tests ci-dessous sont futurs. Aucun graphe réel encore implémenté.

## Global Constraints

- La consultation est la première tranche proposée.
- Aucune connexion Git distante ni fetch automatique.
- Les agents gardent leurs outils et permissions habituels.
- Historique initial : 200 commits ; incréments de 200 ; plafond 2 000.
- Lecture Git : délai de 15 secondes et plafond de sortie 8 Mio.
- Diff affiché : au plus 1 Mio ; signaler la troncature.
- Garder la palette Iris, les icônes SVG, les libellés accessibles et la navigation clavier.
- Un fichier peut appartenir à deux groupes : index et dossier de travail.
- Aucun stage, commit, checkout, merge, rebase, reset ou push dans cette vue.

## Review Focus

1. Dépôt vide, sans Git, HEAD détachée ou `.git` fichier de worktree : G1 relève
   l'état réel, sans construire les chemins internes de Git à la main.
2. Renommages et chemins contenant espaces/accents ou ressemblant à une option :
   G1 parse NUL et passe les chemins littéralement à Git.
3. Merge à plusieurs parents et parent hors page : G2 conserve tous les liens,
   G3 permet de choisir le parent de comparaison.
4. Changements externes pendant la lecture/pagination : G1 fixe les OID de départ,
   G3 conserve sélection et signale un relevé modifié.
5. Binaire, gros diff et lien symbolique sortant du dépôt : G1/G3 bornent la lecture,
   indiquent la limite et ne suivent pas les liens.

## Fichiers et contrats

Créer `src/shared/git.ts` ; le contrat s'ajoute au preload de la V0 sous `git`.
Les IDs de relevé sont générés par le main, et leurs chemins/fichiers y sont validés.

```ts
export type GitCommit = {
  oid: string; parents: string[]; author: string; date: string; subject: string;
};
export type GitRef = { name: string; oid: string; kind: 'local' | 'remote' | 'tag' };
export type ChangeArea = 'index' | 'worktree' | 'untracked' | 'conflict';
export type GitChange = {
  id: string; path: string; oldPath?: string; area: ChangeArea; status: string;
};
export type GitSnapshot = {
  id: string; projectId: string; capturedAt: string;
  root: string | null;
  state: 'ready' | 'unborn' | 'not-repository' | 'git-unavailable';
  head: string | null; branch: string | null; refs: GitRef[];
  commits: GitCommit[]; changes: GitChange[];
  truncated: boolean; changedDuringRead: boolean;
};
export type CommitChange = { id: string; path: string; oldPath?: string; status: string };
export type GitDiff = {
  kind: 'text' | 'binary' | 'submodule' | 'symlink';
  text: string; truncated: boolean;
};
export type DiffTarget =
  | { kind: 'local'; changeId: string }
  | { kind: 'commit'; oid: string; parent: string | null; changeId: string };
export interface GitApi {
  read(projectId: string): Promise<GitSnapshot>;
  loadMore(snapshotId: string): Promise<GitSnapshot>;
  commitFiles(snapshotId: string, oid: string, parent: string | null): Promise<CommitChange[]>;
  diff(snapshotId: string, target: DiffTarget): Promise<GitDiff>;
}
```

Le pont enveloppe ces réponses dans `Result<T>` de la V0 ; erreurs typées
`GIT_TIMEOUT`, `GIT_OUTPUT_LIMIT`, `STALE_SNAPSHOT`, `INVALID_TARGET`, `GIT_FAILED`.
Le main expose `GitReader implements GitApi`. Aucun argument CLI arbitraire
n'entre par IPC. Un projet ouvert hors racine Git conserve son dossier de chat ;
la vue affiche explicitement la racine du dépôt déterminée par Git.

```ts
import { expect, test } from 'vitest';
import { parseStatus } from '../src/main/git/parse-status';
test('conserve les deux chemins du renommage NUL et le non suivi', () => {
  const raw = Buffer.from('R  docs/nouveau été.md\0docs/ancien nom.md\0?? -note.md\0');
  expect(parseStatus(raw)).toEqual(expect.arrayContaining([
    expect.objectContaining({ path: 'docs/nouveau été.md', oldPath: 'docs/ancien nom.md', area: 'index' }),
    expect.objectContaining({ path: '-note.md', area: 'untracked' }),
  ]));
});
```

```ts
const statusArgs = ['--no-pager', 'status', '--porcelain=v1', '-z', '--untracked-files=all'];
const logArgs = ['--no-pager', 'log', '--topo-order', '-z',
```

  simplifie l'ordre topologique sans dupliquer les lignes déjà présentes.

  sans prétendre à une transaction atomique sur le dépôt.
- [ ] Implémenter les différences : `git diff` pour worktree, `git diff --cached`

  merges. Utiliser `--literal-pathspecs` global et `--` avant les chemins.
  Recenser les fichiers de commit via `diff-tree --name-status -z` et les mêmes

- [ ] Pour non suivis, lire au plus 1 Mio après vérification du chemin réel et
  `lstat` ; un lien donne son chemin cible comme texte, sans lecture de la cible.
  Distinguer binaire/sous-module/conflit. Les conflits sont signalés, aucun bouton
  de résolution n'est ajouté. Tronquer de façon explicite si le diff dépasse le

- [ ] Tester arguments optionnels malveillants, chemin `:(glob)*`, lien hors dépôt

## G2 — Graphe SVG des commits et références

**Fichiers :** créer `src/renderer/src/git/layout.ts`, `CommitGraph.tsx`,
`CommitDetails.tsx`, `git.css`, `tests/git-layout.test.ts`.
Modifier le shell pour exposer une vue Git par projet.

**Interfaces :** `layoutGraph(commits: GitCommit[]): GraphLayout` dans `layout.ts` :

```ts
export type GraphLayout = {
  nodes: { oid: string; row: number; lane: number }[];
  edges: { from: string; to: string; outside: boolean }[];
};
```

`CommitGraph({snapshot, onSelect}: {snapshot: GitSnapshot; onSelect(oid: string): void})`
consomme uniquement les données du main. `CommitDetails` affiche parents et références.

- [ ] Écrire le test de merge, puis le cas d'un parent hors fenêtre et trois parents.

```ts
import { expect, test } from 'vitest';
import { layoutGraph } from '../src/renderer/src/git/layout';
test('le merge garde ses deux parents, même hors de la fenêtre', () => {
  const graph = layoutGraph([
    { oid: 'merge', parents: ['left', 'right'], author: 'A', date: '', subject: 'merge' },
    { oid: 'left', parents: [], author: 'A', date: '', subject: 'left' },
  ]);
  expect(graph.edges).toEqual(expect.arrayContaining([
    { from: 'merge', to: 'left', outside: false },
    { from: 'merge', to: 'right', outside: true },
  ]));
});
```

- [ ] Exécuter `npm test -- tests/git-layout.test.ts` avant implémentation. Ajouter
  une histoire linéaire, diamant, racines indépendantes et stabilité du préfixe
  quand la limite passe de 200 à 400 commits.
- [ ] Implémenter les voies de façon déterministe : parcourir l'ordre topologique,
  garder la voie d'un OID déjà attendu, en allouer une sinon ; réserver le premier
  parent dans sa voie et les autres parents dans des voies disponibles. Conserver
  une voie déjà réservée pour un parent commun, sans dupliquer ce parent. Conserver
  les voies de branches encore ouvertes. Dériver les arêtes de tous les parents,
  sans les inventer à partir des dates. La présence en page ne modifie pas la voie
  déjà choisie pour un préfixe ; les liens hors page finissent par un marqueur.
- [ ] Rendre les traits/nœuds en SVG et le texte dans des lignes sélectionnables
  synchronisées. Préserver Iris, contrastes et focus clavier ; afficher OID court,
  sujet, auteur, date et badges de références sans uniquement coder par couleur.
  `HEAD` détachée est un badge explicite. Éviter les animations pendant le streaming.
- [ ] Relier sélection au détail et « Charger plus » à `loadMore` ; conserver scroll
  et sélection par OID. Au plafond afficher « 2 000 commits affichés ». Faire une
  mesure sur une fixture de 2 000 commits et relever le résultat avant d'envisager

## G3 — Arborescence des changements, diffs et recette

**Fichiers :** créer `src/renderer/src/git/ChangesTree.tsx`, `DiffView.tsx`,
`GitView.tsx`, `tree.ts`, `tests/git-view.test.tsx`, `tests/git-tree.test.ts`,

**Interfaces :** `buildChangeTree(changes: GitChange[]): ChangeTreeNode[]` dans
`tree.ts` ; `ChangeTreeNode` est
`{name: string; path: string; children: ChangeTreeNode[]; changes: GitChange[]}`.
`GitView({projectId}: {projectId: string})` appelle `GitApi` via le pont ;
`DiffView({diff}: {diff: GitDiff})` affiche les lignes sans interpréter leur HTML.

- [ ] Écrire le test de fichier partagé index/worktree, puis les tests UI de
  changement de projet pendant une lecture, parent de merge et retour au chat
  avec brouillon intact.

```ts
import { expect, test } from 'vitest';
import { buildChangeTree } from '../src/renderer/src/git/tree';
test('préserve deux versions consultables pour un fichier', () => {
  const tree = buildChangeTree([
    { id: 'a', path: 'src/a.ts', area: 'index', status: 'M' },
    { id: 'b', path: 'src/a.ts', area: 'worktree', status: 'M' },
  ]);
  expect(tree[0].children[0].changes.map(change => change.area)).toEqual(['index', 'worktree']);
});
```
